# CURIOUS REALITY — SEO RULES

## STATUS

Document Type: Search Engine Optimization, Discoverability & Search Architecture
Brand: Curious Reality
Authority: Derived from CURIOUS_REALITY_MASTER_ARCHITECTURE.md

Purpose:

Define how Curious Reality content, website pages, videos, articles, metadata, structured data, internal links, and search architecture should be prepared for long-term discoverability.

The goal is not to manipulate search engines.

The goal is to make genuinely useful Curious Reality knowledge easy for:

- people;
- search engines;
- website systems;
- YouTube;
- future AI systems

to discover, understand, and connect.

The Master Architecture remains the highest-level strategic source of truth.

---

# 1. CORE SEO PRINCIPLE

SEO is not a separate layer from content quality.

The correct relationship is:

USEFUL CONTENT
+
CLEAR INFORMATION ARCHITECTURE
+
SEARCH UNDERSTANDING
+
TECHNICAL ACCESSIBILITY
+
STRUCTURED DATA
=
LONG-TERM DISCOVERABILITY

SEO should serve the actual content.

Do not create content only to satisfy search engines.

---

# 2. PRIMARY SEO OBJECTIVE

Curious Reality should become discoverable through:

- Google Search;
- YouTube Search;
- YouTube Browse;
- YouTube Suggested;
- direct brand searches;
- website internal search;
- related-content discovery;
- external links;
- topic-based discovery.

The long-term objective is:

When people search for a question that Curious Reality genuinely answers, the appropriate Curious Reality content should be eligible to be discovered.

---

# 3. SEARCH PHILOSOPHY

The brand should optimize for:

QUESTIONS

not merely:

KEYWORDS

Examples:

Instead of thinking only:

"battery"

think:

"Why does a phone battery lose capacity?"

Instead of:

"DNS"

think:

"How does DNS actually find a website?"

Instead of:

"camera sensor"

think:

"How does a tiny camera sensor turn light into an image?"

Search optimization should reflect what people actually want to understand.

---

# 4. SEARCH INTENT

Before optimizing a page, identify the search intent.

Possible intent types:

INFORMATIONAL

The user wants to understand something.

EXPLANATORY

The user wants to know how or why something works.

COMPARATIVE

The user wants to understand a difference.

INVESTIGATIVE

The user wants deeper context or evidence.

NAVIGATIONAL

The user wants to find a specific Curious Reality page or brand.

CURRENT

The user wants updated information about something changing over time.

A page should satisfy the primary intent instead of merely matching words.

---

# 5. QUESTION-FIRST SEO

The central question should appear naturally in the page structure where appropriate.

Possible locations:

- page title;
- H1;
- introduction;
- article body;
- section heading;
- metadata;
- structured data;
- related-question links.

Do not force the exact same phrase repeatedly.

---

# 6. KEYWORD PRINCIPLE

Keywords are useful for understanding search language.

They are not a license for keyword stuffing.

Use terminology that naturally describes:

- the subject;
- the mechanism;
- the question;
- the audience's likely wording;
- important related concepts.

Prioritize semantic relevance.

---

# 7. KEYWORD RESEARCH

When researching search demand, identify:

PRIMARY QUESTION

SECONDARY QUESTIONS

RELATED TERMS

TECHNICAL TERMS

COMMON WORDING

ALTERNATIVE WORDING

LONG-TAIL QUESTIONS

MISCONCEPTION TERMS

The purpose is to understand how people search.

Do not create a keyword list disconnected from the actual content.

---

# 8. PRIMARY SEARCH TERM

Each major page should normally have one primary search concept.

Example:

Primary:

How does a smartphone camera work?

Related:

phone camera sensor

how smartphone cameras capture images

CMOS image sensor explained

computational photography

The page should remain focused on the underlying subject.

---

# 9. LONG-TAIL SEARCH

Long-tail searches are especially relevant to Curious Reality because the brand is question-driven.

Useful patterns include:

- why does X happen;
- how does X work;
- what happens when X;
- why is X like this;
- where does X go;
- how is X possible;
- what is actually happening when X.

Long-tail search should be supported by genuinely useful explanations.

---

# 10. SEARCH-TERM NATURALNESS

Use natural language.

Do not write:

"camera camera sensor smartphone camera how camera works camera explanation"

Write a clear sentence that naturally answers the question.

The reader comes first.

---

# 11. TITLE SEO

Every important website page should have a unique title.

The title should:

- describe the page accurately;
- communicate the central question or subject;
- be understandable out of context;
- avoid unnecessary repetition;
- avoid misleading promises;
- differentiate the page from other pages.

The title is both a search signal and a user-facing label.

---

# 12. VIDEO PAGE TITLE

For a video page, the title should normally align with the actual YouTube video subject.

The website should not create a completely unrelated SEO title merely to target a different search.

Where useful, a page title may clarify the subject more explicitly while preserving the video's identity.

Example:

YouTube:

How Does a Smartphone Camera Actually Work?

Website:

How Does a Smartphone Camera Actually Work? | Curious Reality

The exact implementation may vary.

---

# 13. META DESCRIPTION

Important pages should have a unique meta description.

The description should:

- summarize the actual page;
- contain useful natural terminology;
- communicate the knowledge payoff;
- help users understand what they will find;
- avoid keyword stuffing;
- avoid false claims.

Do not write descriptions designed only to contain keywords.

---

# 14. META DESCRIPTION PRINCIPLE

A good description should answer:

What is this page about?

Why might the reader care?

What will they understand?

Example pattern:

"Explore how smartphone camera sensors convert light into electrical signals and how image processing turns those signals into the photos you see."

The exact wording should reflect the actual page.

---

# 15. UNIQUE PAGE METADATA

Do not use one generic title and description across the entire site.

Each important page should have metadata that reflects its own content.

Avoid:

Every page title:
Curious Reality

Every page description:
Learn interesting things at Curious Reality.

Instead:

Page-specific metadata should describe page-specific knowledge.

---

# 16. H1 RULE

Each primary public page should have a clear main heading.

The H1 should represent the main topic or question.

Do not use multiple unrelated H1 elements merely for visual styling.

---

# 17. HEADING HIERARCHY

Use headings logically:

H1
→ primary page topic

H2
→ major sections

H3
→ subsections

Do not select heading levels based only on font size.

Heading structure should reflect content hierarchy.

---

# 18. CONTENT DEPTH

Search optimization should not be measured only by text length.

A page should contain enough information to satisfy the user's question responsibly.

Some questions require:

short explanation

Others require:

detailed investigation

Content length should follow knowledge requirements.

Do not add filler simply to make the article longer.

---

# 19. PEOPLE-FIRST CONTENT

Website content should primarily be written for people.

The content should:

- answer the actual question;
- explain the mechanism;
- provide context;
- cite important evidence;
- preserve uncertainty;
- connect related knowledge;
- remain readable.

Search engines should discover the value that already exists.

---

# 20. ORIGINALITY

Curious Reality website content should add original value.

Originality may come from:

- research;
- framing;
- explanation;
- synthesis;
- visual explanation;
- examples;
- context;
- relationships between concepts.

Do not simply copy another website's article.

Do not rewrite another article sentence-by-sentence.

---

# 21. VIDEO DESCRIPTION VS WEBSITE ARTICLE

The website should not simply duplicate the YouTube description.

The YouTube description may provide concise metadata and context.

The website article should provide deeper value where appropriate.

Possible additional information:

- mechanism;
- research context;
- detailed explanation;
- evidence;
- sources;
- related questions;
- related concepts;
- additional examples.

---

# 22. CANONICAL URL

Every important indexable page should have one canonical URL.

The canonical URL should represent the preferred public version of that page.

Avoid creating unnecessary duplicate URL variants.

---

# 23. URL STRUCTURE

Preferred URLs should be:

- readable;
- stable;
- lowercase;
- descriptive;
- short where practical;
- hyphen-separated.

Example:

```text
https://curiousreality.github.io/videos/how-does-a-camera-work/
```

Avoid:

```text
/video?id=123
/page1
/test
/final-final
```

unless a technical requirement makes another structure necessary.

---

# 24. URL STABILITY

Once an important page is publicly indexed, do not casually change its URL.

If a URL must change:

- preserve the old URL where practical;
- redirect appropriately when the platform supports it;
- update internal links;
- update canonical references;
- update sitemap entries.

A stable archive is valuable.

---

# 25. INTERNAL LINKING

Internal linking is a core part of the knowledge architecture.

Where meaningful, connect:

VIDEO
→ RELATED VIDEO

VIDEO
→ ARTICLE

VIDEO
→ RELATED QUESTION

VIDEO
→ TOPIC

ARTICLE
→ VIDEO

ARTICLE
→ RELATED ARTICLE

ARTICLE
→ SOURCE

QUESTION
→ RELATED QUESTION

Internal links should reflect real relationships.

---

# 26. INTERNAL LINKING PURPOSE

Internal linking should help users:

- understand more deeply;
- discover related concepts;
- continue learning;
- move through the archive;
- find relevant videos.

It should also help search engines understand site relationships.

Do not add meaningless links purely to increase link counts.

---

# 27. RELATED CONTENT

A page may recommend:

- related videos;
- related questions;
- deeper explanations;
- same-topic content;
- follow-up content;
- comparison content.

Recommendations should be semantically relevant.

Popularity alone is not sufficient.

---

# 28. TOPIC CLUSTERS

Where enough content exists, create topic clusters.

Example:

```text
Internet
├── How does the internet work?
├── What happens when you open a website?
├── How does DNS work?
├── Where is a website stored?
└── How does a browser render a page?
```

The cluster should represent a real conceptual relationship.

---

# 29. TOPIC AUTHORITY

Long-term search visibility should emerge from useful coverage of connected questions.

Do not attempt to manufacture authority through large volumes of thin pages.

Instead build:

Question
→ Explanation
→ Related Question
→ Deeper Explanation
→ Source
→ Related Topic

Over time, this can create a strong knowledge archive.

---

# 30. SITEMAP

The website should maintain a valid XML sitemap.

The sitemap should contain publicly indexable canonical URLs.

Exclude:

- irrelevant internal files;
- private content;
- draft-only pages;
- duplicate URLs;
- broken pages.

---

# 31. SITEMAP UPDATE

When a new published video page is created:

1. Generate the page.
2. Add the canonical URL to the sitemap.
3. Ensure the page is internally linked.
4. Deploy the updated site.

The build system should automate this wherever possible.

---

# 32. ROBOTS.TXT

The website should provide a valid robots.txt.

Default principle:

Allow legitimate crawling of public content.

Do not accidentally block:

- public pages;
- stylesheets;
- required scripts;
- important assets;
- sitemap discovery.

Do not use robots.txt as a substitute for proper page management.

---

# 33. INDEXABILITY

Important public pages should be indexable unless there is a deliberate reason not to index them.

Check for:

- accidental noindex;
- blocked crawling;
- inaccessible URLs;
- broken canonical references;
- missing internal links;
- incorrect robots directives.

---

# 34. DRAFT CONTENT

Draft content should not accidentally become public search content.

Draft material should not normally appear in:

- public archive;
- public sitemap;
- public navigation;
- indexable content.

Publication status should control visibility.

---

# 35. 404 HANDLING

The website should provide a useful 404 page.

The page should:

- clearly indicate that the page was not found;
- preserve site branding;
- provide useful navigation;
- help the visitor return to the main site.

Do not return a misleading successful page for missing URLs.

---

# 36. STRUCTURED DATA

Where appropriate, use structured data to describe page content.

Potential types include:

- VideoObject;
- Article;
- BreadcrumbList;
- Organization;
- WebSite;
- other appropriate schema types.

Only use structured data that accurately describes visible or otherwise valid page content.

Do not mark up content that does not exist.

---

# 37. VIDEOOBJECT

Video pages may use VideoObject structured data.

Where available, include accurate:

- name;
- description;
- thumbnail;
- upload date;
- content URL or embed relationship;
- publisher;
- duration where reliably available.

Do not fabricate missing values.

---

# 38. ARTICLE STRUCTURED DATA

Where a page contains a genuine article or research explanation, Article structured data may be appropriate.

Metadata should reflect the actual article.

Do not use Article markup on pages that contain only a video player and a few lines of text if the content does not substantively function as an article.

---

# 39. BREADCRUMB STRUCTURED DATA

When a page has a meaningful hierarchy, breadcrumb structured data may help represent the relationship between:

Home
→ Topic
→ Video

or:

Home
→ Videos
→ Video

The structured relationship should match the visible navigation model.

---

# 40. ORGANIZATION STRUCTURED DATA

Curious Reality may use Organization structured data to communicate core identity.

Potential information:

- name;
- logo;
- website;
- official YouTube presence;
- other official identity references where appropriate.

Only publish accurate organization information.

---

# 41. WEBSITE IDENTITY

Search engines should be able to understand that:

Curious Reality website

and:

Curious Reality YouTube channel

belong to the same ecosystem.

Keep consistent:

- brand name;
- official URLs;
- logo;
- organization identity;
- canonical references.

---

# 42. OPEN GRAPH

Important pages should include appropriate Open Graph metadata.

Where appropriate include:

- title;
- description;
- canonical URL;
- image;
- site name.

The metadata should represent the actual page.

---

# 43. SOCIAL PREVIEW

Social metadata should provide a useful preview when a page is shared.

Images should:

- match the page;
- be accessible;
- have appropriate dimensions;
- avoid misleading representations.

---

# 44. IMAGE SEO

Important images should use meaningful filenames where practical.

Example:

```text
smartphone-camera-sensor.webp
```

instead of:

```text
IMG_4837.webp
```

Where appropriate, provide descriptive alt text.

Alt text should describe the image's useful content or function.

---

# 45. ALT TEXT

Alt text should be:

- descriptive;
- concise;
- relevant;
- useful to accessibility users.

Do not stuff keywords into alt text.

Do not describe decorative images as if they are informational.

---

# 46. IMAGE PERFORMANCE

Images should be optimized for:

- appropriate dimensions;
- reasonable file size;
- modern formats where supported;
- fast loading.

Do not sacrifice necessary visual quality.

Do not serve enormous assets when a smaller version provides the same useful result.

---

# 47. PAGE SPEED

The website should remain lightweight.

Avoid unnecessary:

- JavaScript;
- heavy libraries;
- oversized images;
- blocking assets;
- duplicate requests;
- decorative effects that provide no meaningful value.

Visual quality should not destroy performance.

---

# 48. MOBILE SEO

Curious Reality must work well on mobile devices.

Check:

- text readability;
- responsive layout;
- touch targets;
- navigation;
- video playback;
- image scaling;
- page loading;
- content visibility.

Do not build desktop-only experiences.

---

# 49. CORE PAGE EXPERIENCE

The site should aim for:

- fast loading;
- stable layout;
- usable navigation;
- readable text;
- responsive interaction;
- accessible content.

Performance is part of the overall user experience.

---

# 50. ACCESSIBILITY AND SEO

Accessible content often improves usability and machine understanding.

Use:

- semantic HTML;
- descriptive links;
- logical headings;
- meaningful button labels;
- alt text where appropriate;
- keyboard accessibility;
- sufficient contrast.

Accessibility is not merely an SEO trick.

It is part of quality.

---

# 51. LINK TEXT

Internal links should use meaningful link text where practical.

Prefer:

"How DNS actually works"

over:

"Click here"

The user should understand what the link leads to.

---

# 52. WEBSITE SEARCH

The internal website search should eventually search across:

- video titles;
- questions;
- topics;
- article content;
- concepts;
- tags;
- related terms.

Search results should prioritize relevance rather than arbitrary ordering.

---

# 53. SEARCH RESULT QUALITY

Internal search should avoid returning:

- draft content;
- duplicate pages;
- irrelevant matches;
- broken pages.

Where useful, show:

- title;
- type;
- short description;
- topic;
- relevant relationship.

---

# 54. GOOGLE SEARCH CONSOLE

Google Search Console should be used as the primary Google search monitoring system.

Use it to:

- verify the website;
- submit the sitemap;
- inspect URLs;
- request indexing where appropriate;
- inspect indexing status;
- identify crawl issues;
- monitor search performance;
- identify search queries;
- investigate indexing problems.

Search Console is a monitoring and submission tool.

It does not guarantee ranking.

---

# 55. SITEMAP SUBMISSION

The official sitemap should be submitted to Google Search Console.

Canonical sitemap:

```text
https://curiousreality.github.io/sitemap.xml
```

The sitemap should remain accessible to crawlers.

---

# 56. URL INSPECTION

Important newly published pages may be checked with URL Inspection.

Use it to verify:

- whether the URL is known;
- whether crawling is possible;
- canonical selection;
- indexing status;
- page accessibility.

Request indexing when appropriate.

Do not repeatedly request indexing unnecessarily.

---

# 57. INDEXING VS RANKING

These are different.

INDEXING means:

Google has discovered and stored the page in its index.

RANKING means:

The page is being ordered for a search query.

A page may be indexed without ranking highly.

SEO work should therefore address both:

TECHNICAL DISCOVERABILITY

and:

CONTENT VALUE.

---

# 58. SEARCH PERFORMANCE

Monitor:

- impressions;
- clicks;
- click-through rate;
- average position;
- queries;
- indexed pages;
- pages receiving search traffic;
- emerging search terms.

Do not evaluate the entire strategy from one day's data.

---

# 59. SEARCH QUERY LEARNING

Search queries can reveal:

- what people actually call the topic;
- unexpected questions;
- content gaps;
- terminology differences;
- new follow-up opportunities.

Use these signals to improve:

- titles;
- article structure;
- future questions;
- topic clusters.

Do not blindly add every search query as a keyword.

---

# 60. SEO AND VIDEO INDEX

Every important video record should track where practical:

```text
seo_title
meta_description
canonical_url
keywords
topic_terms
search_questions
structured_data_status
sitemap_status
indexing_status
```

This keeps SEO connected to the video archive.

---

# 61. SEO AND QUESTION ARCHIVE

Questions are one of the strongest SEO assets in Curious Reality.

A question can generate:

- search-oriented article;
- video page;
- related question;
- topic cluster;
- follow-up content.

The Question Archive should therefore feed the SEO system.

---

# 62. SEO AND KNOWLEDGE GRAPH

The Knowledge Graph can help create meaningful internal relationships.

For example:

QUESTION
→ VIDEO
→ CONCEPT
→ RELATED VIDEO
→ ARTICLE
→ SOURCE

These relationships can improve:

- user discovery;
- crawl paths;
- topical understanding;
- content organization.

Only use real relationships.

---

# 63. SEO AND SOURCES

Where an article makes important factual claims, sources should be clearly associated with the relevant content.

The purpose is:

TRACEABILITY
+
TRUST
+
UNDERSTANDING.

Do not add a source list merely to make an article look authoritative.

---

# 64. SEO FOR CURRENT INFORMATION

For time-sensitive subjects:

- use accurate dates;
- update titles/descriptions when necessary;
- update article content;
- update sources;
- preserve the last-updated state where useful;
- ensure outdated claims are not presented as current.

Current information should not be allowed to silently age.

---

# 65. SEO FOR EVERGREEN CONTENT

Evergreen pages should focus on:

- durable questions;
- strong explanations;
- useful structure;
- related concepts;
- long-term readability.

Where new evidence changes the answer, update the content rather than creating unnecessary duplicate pages.

---

# 66. SEO FOR NEWS-LIKE CONTENT

Curious Reality should not become a generic news site.

When current events are covered, the page should still answer a meaningful question.

Examples:

What actually happened?

How does this system work?

Why did this happen?

What does the evidence show?

What remains uncertain?

---

# 67. SEO FOR SENSITIVE SUBJECTS

For sensitive subjects:

- use precise terminology;
- avoid sensational metadata;
- preserve uncertainty;
- distinguish allegation from fact;
- avoid misleading images;
- use strong sources;
- provide appropriate context.

Do not sacrifice accuracy for search traffic.

---

# 68. SEO FOR MYSTERY CONTENT

Mystery pages should remain fact-based.

Use language such as:

- unexplained;
- unresolved;
- disputed;
- evidence suggests;
- known;
- unknown.

Do not turn uncertainty into false certainty merely because sensational wording may attract clicks.

---

# 69. SEARCH SNIPPET HONESTY

Titles and descriptions should accurately reflect the content.

Do not create a snippet that promises:

"Complete explanation"

when the page only contains a short summary.

Do not create a title that implies evidence the page does not contain.

---

# 70. KEYWORD STUFFING BAN

Never create pages like:

```text
AI AI AI artificial intelligence AI technology AI explained AI tools AI model
```

or unnatural keyword blocks.

Use normal language.

Search systems should understand semantic context.

---

# 71. HIDDEN TEXT BAN

Do not use hidden keyword text for SEO manipulation.

Do not place irrelevant keywords:

- off-screen;
- transparent;
- microscopic;
- behind elements;
- in CSS-only search blocks.

All meaningful text should exist for users.

---

# 72. DUPLICATE CONTENT RULE

Avoid creating many pages that differ only superficially.

Examples of weak duplication:

```text
/how-does-a-battery-work/
/how-does-battery-work/
/battery-how-it-works/
/battery-explained/
```

when all four contain the same content.

Prefer one strong canonical page.

---

# 73. CANONICAL DUPLICATE RULE

When duplicate versions are unavoidable:

- identify the preferred canonical;
- link internally toward the canonical;
- use correct canonical metadata;
- keep sitemap focused on canonical URLs.

---

# 74. THIN CONTENT RULE

Do not create pages solely because a keyword exists.

A page should contain meaningful value.

Thin pages include:

- one paragraph with no useful explanation;
- copied metadata;
- automatically generated filler;
- duplicate text;
- keyword-only pages.

A smaller archive of strong pages is preferable to thousands of weak ones.

---

# 75. PROGRAMMATIC SEO RULE

Automation is encouraged for:

- page generation;
- metadata templates;
- sitemap updates;
- schema generation;
- URL generation;
- related-content linking.

Automation must not generate large quantities of useless content merely to capture search terms.

---

# 76. STATIC SITE SEO

The Curious Reality website is built as a static site.

The build system should therefore generate:

- final HTML pages;
- metadata;
- canonical URLs;
- structured data;
- sitemap;
- robots.txt;
- internal links.

The generated `public` directory is the deployable search-facing output.

---

# 77. BUILD-TIME SEO

SEO-critical data should ideally be resolved during build time where possible.

Examples:

- video metadata;
- titles;
- descriptions;
- slugs;
- canonical URLs;
- sitemap;
- structured data;
- article relationships.

Build errors should not silently generate invalid SEO.

---

# 78. VIDEO METADATA AUTOMATION

Where reliably available, the website may automatically derive:

- YouTube video ID;
- title;
- thumbnail;
- basic metadata.

However:

Automation must have fallback behavior.

Do not fabricate metadata when external retrieval fails.

Human-provided authoritative information may override unreliable automatic inference.

---

# 79. SHORT VS LONG SEO

Format must remain correct.

Short:

```text
9:16
```

Long:

```text
16:9
```

Do not allow SEO/page generation logic to confuse the two content formats.

The page metadata should describe the actual video.

---

# 80. PUBLISHED CONTENT ONLY

Only published content should normally be eligible for public:

- sitemap;
- search indexing;
- archive discovery;
- structured data.

Draft content should remain controlled.

---

# 81. INTERNAL SITE AUTHORITY

Every important published page should be reachable through the site's internal navigation or another meaningful internal link.

Avoid creating "orphan pages" that exist but are not connected to the site.

---

# 82. ORPHAN PAGE TEST

A page should ideally be discoverable through one or more of:

- homepage;
- videos archive;
- topic page;
- related video;
- related question;
- article;
- search.

An important page with no internal relationship should be reviewed.

---

# 83. ARCHIVE STRUCTURE

As Curious Reality grows, the archive should support:

- videos;
- questions;
- topics;
- articles;
- concepts;
- collections;
- sources.

This creates multiple discovery paths.

---

# 84. SEO CONTENT CLUSTERS

A mature cluster may look like:

```text
TOPIC
│
├── QUESTION
│   └── VIDEO
│       └── ARTICLE
│
├── QUESTION
│   └── VIDEO
│
├── CONCEPT
│   └── ARTICLE
│
└── SOURCE COLLECTION
```

The cluster should represent genuine knowledge relationships.

---

# 85. BRAND SEARCH

The website should consistently communicate the brand name:

Curious Reality

The goal is for users searching the brand to find:

- website;
- YouTube channel;
- relevant official pages;
- recognizable brand identity.

Keep public brand information consistent across platforms.

---

# 86. EXTERNAL DISCOVERY

External links may eventually come from:

- YouTube;
- social platforms;
- articles;
- educational references;
- communities;
- partnerships;
- legitimate citations.

Do not purchase low-quality spam links merely to manipulate rankings.

Focus on useful content people naturally want to reference.

---

# 87. LINK QUALITY PRINCIPLE

A useful external link is more valuable than many irrelevant links.

Prefer:

- relevant websites;
- credible references;
- legitimate mentions;
- editorial references;
- community references where appropriate.

Avoid:

- link farms;
- automated spam;
- irrelevant directories;
- manipulative schemes.

---

# 88. SEO AND BRAND TRUST

Search visibility must never outrank trust.

Never knowingly use:

- false claims;
- fake statistics;
- invented sources;
- deceptive titles;
- misleading thumbnails;
- fabricated authority.

Long-term search visibility depends on the underlying quality of the archive.

---

# 89. SEO AND AI

AI can assist with:

- metadata drafting;
- question extraction;
- keyword clustering;
- internal linking suggestions;
- schema generation;
- content audits;
- search-query analysis;
- topic-gap discovery.

AI must not:

- invent search data;
- invent Google ranking factors;
- fabricate backlinks;
- fabricate sources;
- create fake statistics;
- publish unsupported claims.

---

# 90. SEARCH DATA DISCIPLINE

When using search data, distinguish:

Observed query

Estimated demand

Inference

Hypothesis

Do not present estimated keyword volume as an exact fact unless verified.

---

# 91. SEO EXPERIMENTATION

Experiments may include:

- title refinement;
- description refinement;
- internal-link improvements;
- content structure;
- topic-cluster organization;
- thumbnail changes;
- metadata improvements.

When testing:

Change one meaningful variable where practical.

Measure over an appropriate period.

Avoid conclusions from tiny or noisy datasets.
